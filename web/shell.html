CHIP-8 · emulator and debugger

CHIP-8 is a tiny virtual machine from 1977 — 35 instructions, 4 KB of memory and a 64×32 black-and-white screen. This is an implementation of it written from scratch in C++, compiled to WebAssembly, wrapped in a debugger that shows the machine working while it runs. Click the screen, then press A and D to play.

The six ROMs, and what each one is

Tab cycles through them, and the strip under the screen always names the one you are on and its controls. Every one is original, written by hand in CHIP-8 assembly, with the commented source kept in roms/src/.

What the debugger is for

An emulator is a program pretending to be a computer, and normally you only see what the pretend computer draws. Press H and you see the pretend computer itself: what it is holding, where it is up to, and which instruction it is about to run.

That is what makes a bug findable. When a sprite leaves a stuck pixel behind, no amount of staring at the game says why — but pausing on the frame it happens and stepping one instruction at a time, with the registers next to you, does.

None of it is needed to play. It starts folded away.

Every key, and what each panel means
H
show or hide the debugger
Space
pause and resume
N
run exactly one instruction, while paused
Tab
load the next bundled ROM
Backspace
restart the current ROM
[ ]
instructions per frame — the emulator’s clock speed, 11 by default
F1–F5
toggle the five hardware quirks that real CHIP-8 interpreters disagree about: how shifts pick their operand, whether Fx55/Fx65 leave I moved, whether logic ops clear VF, whether draws wait for vblank, and whether sprites clip or wrap at the edges

With the debugger open:

V0–VF
the sixteen registers, all the scratch space a program gets. Flashes amber for a moment when one is written
PC
which instruction is next
I
an address register, almost always aimed at a sprite
SP, stack
how deep in subroutine calls the program is
DT, ST
two countdowns ticking 60 times a second — the only clock a ROM has, and how it paces itself. ST also drives the beep
Memory @ I
the bytes I points at, usually the next sprite
Disassembly
the program as instructions rather than hex. It parks over whichever stretch is running hottest instead of chasing the program counter, which at sixty frames a second is unreadable; a green wash means a line ran recently. Pause and it follows the program counter exactly, so N steps line by line
Keypad
reads CHIP-8 value / your key. The original COSMAC VIP had a 16-key hex pad laid out 1 2 3 C / 4 5 6 D / 7 8 9 E / A 0 B F, mapped here onto the left block of a QWERTY keyboard — so pressing A lights CHIP-8 key 7
